# 答辩演示流程

## 1. 演示目标与准备

建议用 8～10 分钟完成一次端到端演示，案例项目名为“企业知识库系统”。首次数据库初始化已提供四类账号、100000 元预算、四个里程碑、三项任务、两条依赖、工时、云支出和三个部署候选方案。演示前可再创建一个已到期未完成任务，用来稳定展示延期传播。

## 2. 演示主线

### 第一步：登录与角色权限（约 40 秒）

1. 使用开发人员 `dev` 登录，展示只列出其已加入项目以及可用的任务、工时功能。
2. 展示预算编辑按钮被隐藏；如需证明服务端鉴权，可用接口测试工具以开发者 token 调用 `PUT /api/projects/1`，结果为 403。
3. 切换项目经理账号，说明 Rust 后端的 JWT 与 RBAC 校验。

对应课程点：系统环境与开发工具、多角色团队协作。

### 第二步：项目、里程碑与任务分工（约 1 分钟）

1. 打开“企业知识库系统”，展示负责人、周期、预算和成员。
2. 展示需求设计、系统开发、联调测试、项目交付四个里程碑。
3. 在任务看板查看“需求确认、Rust后端接口、系统联调”三项种子任务，打开详情说明负责人、预计工时、验收标准和参与者。

对应课程点：项目生命周期、WBS 和团队分工。

### 第三步：依赖检测与延期影响（约 1 分钟）

1. 展示种子依赖链“需求确认 → Rust后端接口 → 系统联调”。
2. 项目经理创建一个计划结束日期早于当天的未完成任务，并将“Rust后端接口”设置为依赖它；风险页可显示延期任务及其下游影响。
3. 尝试让该延期任务再依赖“系统联调”，这会闭合环路，展示 Rust 后端拒绝。
4. 调用下游分析或查看风险原因，说明受影响任务 ID、负责人和阻塞原因。

对应创新点：任务依赖图、循环检测和风险传播。

### 第四步：工时、负载、成本与 EVM（约 2 分钟）

1. 使用开发人员新增一条“Rust后端接口”任务工时，说明人力成本按工时乘用户时薪计算。
2. 使用项目经理新增一笔云服务支出；如需稳定构造 CPI < 1，可在演示副本中录入约 60000 元测试环境支出。
3. 展示人力成本、设备/云服务/采购/其他分类、项目总成本、预算使用率和累计成本趋势。
4. 打开风险页说明 PV、EV、AC、BAC、SPI、CPI、EAC；在上述数据下观察进度/成本健康度以及 EAC 超预算风险。
5. 展示成员负载；种子开发任务预计工时已超过默认 40 小时周容量，可看到超过 100% 的负载预警。

对应课程点：资源管理和成本核算。对应创新点：进度与成本联动分析。

### 第五步：开发—评审—测试闭环（约 1 分钟）

1. 开发人员将“Rust后端接口”从“进行中”提交到“待评审”。
2. 评审人员填写意见并驳回，任务回到“进行中”；空驳回理由会被后端拒绝。
3. 修正后再次提交，依次评审通过、测试通过，任务进入“已完成”。
4. 展示评论、评审和操作记录，说明 `review/testing` 两阶段由评审角色控制。

对应课程点：不同角色的工作交接和质量管理。

### 第六步：技术方案经济决策（约 2 分钟）

1. 打开“部署方式选择”，展示自建服务器、公有云、混合云三个方案。
2. 展示统一分析期、成本、收益、风险概率和风险损失。
3. 展示指标方向、权重合计与方案原始值。
4. 执行评价，查看 TCO、ROI、综合得分柱状图、排名，以及由服务端 `scores` 标准分绘制的雷达图。
5. 朗读系统生成的主要优势与不足，强调推荐由 Rust 规则生成、未调用大模型。
6. 项目经理可选择推荐方案或其他方案，但必须填写理由；确认后展示确认方案名称和理由，并演示“不可重新评价”的只读约束。

对应创新点：可解释、可追溯的经济决策。

### 第七步：综合仪表盘与总结（约 40 秒）

展示项目完成率、各状态任务数量、预算使用率、成本趋势、SPI/CPI、延期任务、高风险任务、成员负载、近期里程碑和最新预警。

总结表述：

> RustFlow 以研发任务协作为基础，用依赖分析和 EVM 管理工程风险，用 TCO、ROI 和加权评价辅助经济决策，全部核心规则由 Rust 实现，最终决策由项目负责人确认。

## 3. 异常备用方案

- 演示前保留数据库副本，避免现场重复操作破坏数据。
- 准备关键页面截图和一次完整接口测试结果，以应对投影或浏览器故障。
- 若某项指标分母为零，明确展示“暂无数据”，不要临时修改数据库。
- 不演示未完成的扩展功能，不把“后续可做”描述成“已经实现”。

## 4. 答辩常见问题

**为什么不用大模型？** 评分涉及金额和项目决策，需要确定、可解释、可重复测试的结果；Rust 算法负责计算，负责人保留最终决定权。

**Rust 核心逻辑体现在哪里？** 权限、状态机、依赖环检测、延期传播、成本、EVM、风险、TCO/ROI、标准化、加权排序和推荐理由均在后端。

**创新是否只是普通增删改查？** 三个创新点都有明确算法、输入输出、异常处理和可验证结果，并形成任务—管理—决策三个闭环。

**如何证明团队合作？** 展示角色交接流程，并提供需求讨论、Git 提交、代码评审、接口联调和缺陷闭环等真实记录。
