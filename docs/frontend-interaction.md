# 前端功能与交互说明

## 1. 导航与页面

基础版使用桌面端管理后台布局：左侧主导航、顶部项目切换和用户菜单、右侧内容区。仅实现以下页面，不增加扩展功能。

| 页面 | 核心内容 | 主要交互 |
| --- | --- | --- |
| 登录 `/login` | 账号、密码、演示账号提示 | 登录、错误提示、退出后返回登录页 |
| 综合仪表盘 `/dashboard` | 完成率、各状态任务数量、预算使用率、SPI/CPI、风险、成本趋势、负载和近期里程碑 | 用项目选择器切换聚合范围 |
| 项目列表 `/projects` | 项目卡片/表格、状态、经理、日期、预算 | 新建、进入详情 |
| 项目详情 `/projects/:id` | 基本信息、成员、里程碑 | 编辑/归档项目，维护项目成员和里程碑 |
| 任务看板 `/projects/:id/board` | 五列状态、任务卡片 | 新建任务、打开详情、合法状态流转、刷新 |
| 任务详情 `/tasks/:id` | 字段、依赖、评论、评审、操作记录 | 修改、提交评审、评审/测试通过或驳回 |
| 团队与负载 `/team` | 用户、团队成员、项目角色、时薪、可用工时、负载率 | 创建用户/团队，添加成员，查看项目负载 |
| 工时与成本 `/costs` | 工时表、支出表、分类成本、预算差异和 EVM | 登记工时或支出 |
| 风险与绩效 `/risks` | PV/EV/AC/BAC、SPI/CPI/EAC、实时风险列表 | 查看风险，项目经理重新扫描 |
| 技术决策 `/decisions` | 决策列表、录入、排名、雷达/柱状图、确认区 | 创建、评价、查看推荐、人工确认 |

## 2. 关键交互规则

### 登录与权限

- 登录成功后保存 token 和当前用户信息，请求统一附带 Bearer token。
- 收到 401 清理会话并回到登录页；403 显示“无权执行此操作”。
- 菜单和按钮按系统角色隐藏；项目内最终权限由后端的 `project_members.project_role` 判断，前端隐藏按钮不能作为安全边界。

### 项目与任务

- 归档操作必须二次确认，并提示归档后整个项目只读，任务、成员、里程碑、依赖、工时、支出、风险扫描和决策写操作都不可继续。
- 看板卡片至少显示标题、负责人、优先级、截止日期、完成比例和阻塞标识。
- 状态变化不能只在浏览器内完成；先调用后端，成功后更新列，失败则恢复原状并显示原因。
- 驳回时使用弹窗强制填写评审意见。
- 新增依赖时排除当前任务和其他项目任务；后端返回环路错误时展示完整错误信息。

### 工时、金额与指标

- 工时大于 0，按 0.5 小时递增；金额显示两位小数。
- 权重编辑时实时显示合计；创建时转换为基点，后端强制校验合计为 10000。
- TCO、ROI 和综合评分均以服务端结果展示，前端不得用另一套公式重新计算。
- 雷达图读取每个评价结果的 `scores` 标准分字典，不把成本、百分比和主观评分的原始值直接混画。
- SPI/CPI 无有效分母时显示“暂无数据”，而非 0、无穷或错误颜色。

### 风险展示

- 风险等级统一为高、中、低，对应红、橙、蓝；颜色之外同时显示文字。
- 依赖影响采用“逾期任务 → 下游任务”的层级列表，不要求实现复杂拓扑图。
- 每条风险必须显示触发原因，避免只有一个不可解释的分数。

## 3. 技术决策分步页

1. 决策信息：名称、说明、分析年限。
2. 候选方案：至少两个方案，录入成本、收益和风险数据。
3. 评价指标：名称、方向、权重，合计 100%。
4. 指标矩阵：为每个方案录入原始值；TCO/ROI 的占位值会由 Rust 计算结果覆盖。
5. 结果分析：TCO/ROI 对比、综合得分柱状图、指标雷达图、排名和推荐理由。
6. 人工确认：评价完成后选择最终方案并填写理由；确认后显示方案名和确认理由，且禁止再次评价。

推荐结果必须同时显示优势与不足，并明确“系统建议不等于最终决定”。不接入大模型 API，说明文本由后端规则模板生成。

## 4. 通用页面状态

每个数据页都应包含：

- 首次加载骨架或加载指示；
- 无数据时的下一步提示；
- 网络或业务失败提示；
- 提交中防重复点击；
- 成功后的明确反馈；

## 5. 演示友好性

- 提供可识别的中文演示数据，避免只出现 ID。
- 首页默认进入一个包含任务、工时、成本、风险和决策数据的示例项目。
- 图表旁显示数值和公式解释，避免答辩时只能看颜色。
- 关键操作完成后无需跳转多个页面即可看到结果变化。
