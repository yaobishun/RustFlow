# 需求范围与验收标准

## 1. 产品目标

RustFlow 服务于 3～4 人研发小组及其项目负责人，解决任务交接不可追踪、任务依赖导致的延期影响不透明、工时与项目成本分离、技术选型缺少量化依据等问题。

系统成功的判断标准：用户能够在浏览器中完成一条完整研发管理链，且所有关键规则和计算由 Rust 后端执行并可重复验证。

## 2. 用户与权限

| 角色层次 | 允许的核心操作 |
| --- | --- |
| 系统 admin | 管理用户、访问全部项目、查询全局操作日志；在项目内视为管理员 |
| 系统 manager | 可创建团队和项目；项目内能力仍以 `project_members.project_role` 为准 |
| 项目 manager | 编辑/归档项目，维护成员、预算、里程碑、任务和依赖，登记支出，扫描风险，创建/评价/确认决策 |
| 项目 developer | 查看所属项目；修改本人负责/参与任务的内容和进度，流转开发阶段，填写工时和评论 |
| 项目 reviewer | 查看所属项目；执行评审与测试的通过或驳回 |

权限必须由后端校验；隐藏前端按钮不能替代接口鉴权。

## 3. 功能需求与验收

### 3.1 登录、团队与用户

- 用户使用账号和密码登录、退出，并可查看当前资料；本人可修改显示名称，管理员可维护用户时薪和启用状态。
- 管理员可维护用户；项目经理可创建团队、添加成员并设置项目角色。
- 非管理员只能看到自己作为项目成员加入的项目和决策；用户必须先加入项目所属团队，才能被加入项目。
- 未登录请求返回 401，无权限请求返回 403。

验收场景：开发人员尝试修改项目预算时被后端拒绝；项目经理可以完成同一操作。

### 3.2 项目与里程碑

- 项目记录名称、描述、负责人、计划日期、预算、状态和成员。
- 有系统创建权限的用户可创建项目；项目 manager 可修改和归档。归档后保留查询和历史数据，所有项目写操作均被后端拒绝。
- 项目可包含多个里程碑，每个里程碑有计划日期和完成状态。
- 项目完成率由任务完成情况计算并在详情页展示。

验收场景：创建包含“需求设计、系统开发、联调测试、项目交付”的项目，并看到正确的整体完成率。

### 3.3 任务看板与协作

- 任务记录所属里程碑、标题、说明、验收标准、负责人、参与者、优先级、计划日期、预计工时、完成比例和状态。
- 看板按“待处理、进行中、待评审、测试中、已完成”展示各状态任务数量和任务卡片。
- 合法主流程为：待处理 → 进行中 → 待评审 → 测试中 → 已完成。
- 评审或测试驳回后返回“进行中”，并强制填写意见。
- 每次状态变化、评论、评审和关键字段修改均形成可追溯记录。接口状态值为 `todo/in_progress/review/testing/done`。

验收场景：开发人员不能跳过评审直接完成任务；评审人员可驳回并留下原因；再次提交后可完成测试。

### 3.4 任务依赖与延期影响

- 可以为任务设置一个或多个前置任务。
- 禁止任务依赖自身，禁止创建循环依赖，禁止跨项目依赖。
- 前置任务未完成时，后置任务不能进入“进行中”。
- 任务逾期时，系统沿有向依赖图搜索全部下游任务，并以 `affected_tasks` 展示受影响任务和负责人。

验收场景：A → B → C 时不能再添加 C → A；A 逾期后，风险页列出 B、C 及其负责人。

### 3.5 工时、负载与成本

- 成员可为本人参与的任务记录工作日期、工时和工作内容。
- 成员/项目角色维护单位工时成本；金额统一用整数“分”、比例统一用整数基点（bps）计算和存储，避免浮点金额误差。
- 支出类型固定为设备、云服务、采购和其他，记录金额、日期和说明。
- 人力成本 = Σ（实际工时 × 单位工时成本）。
- 项目总成本 = 人力成本 + 设备支出 + 云服务支出 + 采购支出 + 其他支出。
- 成员负载率 = 当前未完成任务预计工时 ÷ 当前周期可用工时 × 100%；超过 100% 产生过载预警。

验收场景：新增工时或支出后，总成本和预算使用率同步变化；同一输入重复计算得到相同结果。

### 3.6 EVM 与风险预警

- 系统计算 PV（计划价值）、EV（挣值）、AC（实际成本）、BAC（完工预算）。
- SPI = EV / PV，CPI = EV / AC，EAC = BAC / CPI；分母为零时显示“暂无数据”，不得报错或产生无穷值。
- 风险包括任务逾期、依赖阻塞、成员过载、预算超支和预计完工成本超预算。
- 项目风险查询根据当前任务、成本和负载实时生成类型、等级、原因及关联对象；项目 manager 可执行扫描，将当次活动风险覆盖保存到风险记录表。

验收场景：构造 SPI < 1 且 CPI < 1 的项目，仪表盘显示进度与成本双重风险并给出原因。

### 3.7 技术方案经济决策

- 项目经理创建决策问题、统一分析周期、候选方案和评价指标。
- 权重之和必须为 100%；指标方向为“越大越好”或“越小越好”。
- 系统计算：
  - 预期风险损失 = 风险发生概率 × 风险损失金额；
  - TCO = 初始投入 + 开发成本 + 年运维成本 × 分析年限 + 预期风险损失；
  - ROI =（预期收益 − TCO）/ TCO × 100%；
  - 综合得分 = Σ（指标标准分 × 指标权重）。
- 不同量纲指标采用 min-max 标准化到 0～100。全部方案数值相同时统一记 100 分，避免除零。
- 结果展示 TCO、ROI、综合得分、排名、每项指标的 0～100 标准分 `scores`、优势、不足和基于规则模板的推荐理由。雷达图必须使用服务端 `scores`，不得使用不同量纲的原始值。
- TCO/ROI 指标由 Rust 根据方案经济输入计算并覆盖客户端占位值。
- 系统推荐仅为建议；项目 manager 可确认其他方案，但必须填写选择理由。决策必须先评价才能确认，确认后的输入和结果记录只读且禁止重新评价。

验收场景：一次提交三种部署方案、指标及权重后得到稳定排序和标准分雷达图；选择一个方案并填写理由完成确认；再次调用评价接口被后端拒绝。

### 3.8 综合仪表盘

- 展示项目完成率、各状态任务数量、预算使用率、实际成本累计趋势、SPI、CPI、准确的延期任务数、高风险任务数、成员负载、近期里程碑和最新预警。
- 仪表盘仅汇总当前用户有权访问的项目。

## 4. 非功能要求

- 安全：密码哈希存储，认证令牌有有效期，核心接口执行角色与项目成员双重校验。
- 正确性：金额使用整数分、比例使用整数基点；关联多表写入使用事务；关键计算和核心业务流程有 Rust 自动化测试。
- 可用性：录入表单有中文校验提示；空状态、加载状态、错误状态可辨识。
- 可追溯：任务状态、评审、成本和决策确认均保留操作人及时间。
- 可部署：本地一条脚本可启动前后端，SQLite 自动初始化。

## 5. 明确不在基础版范围内

- 人员智能推荐、技能匹配
- 研发设备借用、归还和冲突检测
- 决策敏感性分析
- PDF/Word 报告导出
- 大模型或第三方 AI API
- 考勤、请假、薪资和绩效考核
- 即时聊天、在线文档、视频会议
- 移动端 App 和复杂多租户

这些内容不得阻塞基础版交付，也不作为验收条件。
