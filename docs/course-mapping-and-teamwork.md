# 课程要求对应、团队分工与过程证据

## 1. 三项要求如何落到项目中

三项要求是对课程实践和报告的综合要求。系统是实践载体，开发过程是真实依据，报告负责解释并提供证据。

| 课程要求 | 系统/开发体现 | 报告应放的证据 |
| --- | --- | --- |
| ① 熟练掌握计算机系统应用环境与开发工具 | Rust/Cargo、Axum、Vue/Vite、SQLx/SQLite、JWT、Git、接口与单元测试、启动脚本 | 开发环境表、目录和架构图、构建运行截图、测试结果、Git 分支与提交记录、典型问题排查 |
| ② 多学科背景下的团队合作 | 项目经理、开发、评审/测试角色；任务分配、评论、开发—评审—测试交接、多人参与技术决策 | 需求与原型讨论、成员分工、Issue、接口约定、Pull Request/代码评审、测试缺陷、会议纪要 |
| ③ 多学科环境中应用工程管理原理与经济决策方法 | 项目/里程碑、WBS 任务、依赖和风险传播、计划/实际工时、负载、预算、EVM、TCO、ROI、加权决策 | WBS 和进度表、风险案例、成本口径与公式、EVM 计算、多个技术方案对比、最终人工决策记录 |

第一项不是要求开发一个“工具管理”功能；第二项不能只靠系统里设置角色；第三项应有系统功能和真实计算案例共同支撑。

## 2. 4 人团队建议分工

| 成员 | 主责 | 必须协作的交叉工作 | 可交付证据 |
| --- | --- | --- | --- |
| A：项目/后端负责人 | 需求管理、认证权限、项目和成员 API、集成 | 与 C 确认接口，与 D 复核验收 | 需求拆分、后端提交、接口评审、迭代记录 |
| B：算法/数据负责人 | 数据模型、任务状态机、依赖图、成本/EVM/决策算法 | 与 A 统一权限，与 D 设计边界测试 | ER 图、算法说明、单元测试、计算样例 |
| C：前端/UI 负责人 | 页面框架、任务看板、成本风险图表、决策交互 | 与 A/B 联调，与 D 修复可用性问题 | 原型、前端提交、联调记录、页面截图 |
| D：测试/文档负责人 | 测试计划、接口测试、缺陷管理、部署、报告材料 | 参与需求验收和经济指标复核 | 测试用例、缺陷单、部署说明、演示脚本 |

3 人团队可合并为：A 负责后端与数据库；B 负责算法与测试；C 负责前端与联调。需求、项目管理、经济分析和报告由三人共同参与，不能完全交给一人。

## 3. 建议开发过程

1. 需求与原型：共同确认基础版边界、角色、核心流程和验收场景。
2. 架构与契约：确定数据模型、API、任务状态机、金额和指标口径。
3. 分模块开发：使用功能分支和 Issue，每个合并请求至少一人评审。
4. 联调与测试：按完整业务链联调，缺陷记录负责人、复现步骤和修复提交。
5. 验收与复盘：运行测试，执行答辩演示脚本，复盘进度偏差和技术决策。

## 4. 报告材料清单

- 环境与工具版本：操作系统、Rust、Cargo、Node.js、npm、SQLite、编辑器、Git 和接口测试工具。
- 系统材料：需求用例、技术架构、ER 图、接口约定、关键页面、核心 Rust 代码说明。
- 管理材料：WBS、里程碑计划、任务看板、工作量分配、风险清单和迭代变化。
- 合作材料：成员分工、会议纪要、提交统计、PR/评审、联调问题和缺陷闭环。
- 经济材料：时薪和支出口径、预算/实际成本、PV/EV/AC、SPI/CPI/EAC、TCO/ROI 和加权评分案例。
- 结果材料：单元/接口/系统测试、部署运行、完整演示结果、局限和后续方向。

## 5. 可直接写入报告的创新点

1. **任务依赖风险传播**：以有向图表示前置关系，在新增依赖时检测环路，在任务延期时搜索全部下游影响对象。
2. **进度与成本联动预警**：采用 EVM 同时衡量工期和成本绩效，并基于当前效率预测完工成本。
3. **可解释的经济决策**：用 TCO、ROI、风险期望损失和多指标加权评分进行排序，同时输出优势、不足和人工确认记录。

创新点不依赖大模型，不包含扩展功能，结果确定、可测试、可复现。
